# Flujo de Escritura MCP

Todas las escrituras MCP siguen el modelo de solo preparación:

```
check_*_readiness (opcional) → prepare_* → firmar → transmitir → get_transaction_status
```

El servidor nunca retransmite transacciones firmadas.

## Respuesta de preparación

La preparación completa devuelve:

- `requestId` — ID de correlación para soporte
- `unsignedTransactions` — calldata para firmar
- `signingMode` — `raw` o `eip5792` (lote approve + subscribe)
- `instructions` — pasos ordenados de firma
- `simulation` — resultados de simulación on-chain
- `gasEstimates` / `gasSummary` — presupuesto de gas orientativo en Base (MCP es solo Base)
- `preflight` — contexto específico de la operación
- `warnings` — sugerencias no fatales
- `eip5792` — descriptor de lote cuando `signingMode` es `eip5792`
- `chainId` — siempre `8453` (MCP es solo Base)

## Campos de request opcionales

En herramientas `prepare_*`:

- **`readinessOnly: true`** — solo preflight; sin transacciones sin firmar ni estimaciones de gas
- **`simulateFromAddress`** — dirección para `eth_estimateGas` cuando el firmante difiere del broadcaster
- **`infiniteApproval: true`** — en `prepare_subscribe` / `prepare_subscribe_by_id`, allowance ERC-20 máxima en lugar de approve acotado al amount

## Modo solo preparación

Pasa `readinessOnly: true` a cualquier herramienta `prepare_*`:

- Devuelve `ready`, `errors`, `warnings`, `details`
- Sin `unsignedTransactions` ni simulación
- Cuenta contra los mismos [límites de tasa](/docs/developers/REST%20API/rate-limits) free/developer que el resto de tools MCP — no hay un cobro por llamada

Herramientas dedicadas de preparación: `check_subscribe_readiness`, `check_subscribe_readiness_by_id` (**preferida** si conoces el id), `check_remit_readiness`.

## Después de transmitir

Consulta `get_transaction_status` con `{ "txHash": "0x…" }`. Incluye `requestId` al reportar problemas.

## Remit

```
check_remit_readiness → prepare_remit → firmar → transmitir → repetir hasta ponerse al día
```

Un `remit()` liquida como máximo `maxRemits` pagos por transacción. Cuando el backlog necesita múltiples transmisiones, `preflight.expectedTransactions` y `gasSummary.backlogMultiplier` describen el presupuesto total de gas.

Consulta el [flujo de caller de remit](/docs/developers/Workflows/remit-caller).
