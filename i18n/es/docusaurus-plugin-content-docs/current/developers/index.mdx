# Visión general para desarrolladores

Clocktower es un protocolo de suscripciones en cadenas EVM. REST usa **Base** por defecto (chainId 8453) y acepta `?chainId=` opcional en rutas de protocolo. **MCP, x402, SIWE y el entitlement Builder permanecen en Base.**

Si construyes una app, backend o agente de IA que necesita pagos recurrentes, cuentas de suscriptores o datos del protocolo, no tienes que montarlo todo solo con llamadas crudas al contrato.

Ofrecemos dos superficies HTTP<IfFeature name="sdk"> más un SDK TypeScript</IfFeature>:

- **API REST** (`api.clocktower.finance`) — consulta suscripciones, cuentas e historial en una cadena de protocolo seleccionada; prepara transacciones que el usuario firma en su wallet.
- **Servidor MCP** (`mcp.clocktower.finance`) — las mismas capacidades como tools para agentes y clientes MCP, con precios x402 por llamada en Base.
<IfFeature name="sdk">
- **SDK TypeScript** — lectura y escritura on-chain directa cuando ya tienes wallet y RPC.
</IfFeature>

Estas superficies responden a las mismas preguntas: *¿Quién está suscrito a qué? ¿Qué vence después? ¿Qué transacción debe firmar el usuario?*

:::warning Pre-lanzamiento
Los endpoints de producción en `api.clocktower.finance` y `mcp.clocktower.finance` pueden seguir en pre-lanzamiento. Consulta `GET /catalog` y los quickstarts para el estado actual.
:::

## Qué puedes construir

**Con REST**, dashboards, backends y apps de navegador: proveedores y suscriptores, historial de pagos, readiness y calldata preparado para creates, updates, cancels y remits. Tu app prepara; el usuario firma.

**Con MCP**, un agente razona sobre el estado vivo del protocolo: discovery, cuentas y writes preparados con tools MCP estándar. Cada tool se paga con x402 en USDC en Base — ideal cuando el llamador es un agente autónomo.

<IfFeature name="sdk">
**Con el SDK**, saltas la API para escrituras y hablas con Base o Base Sepolia vía viem. Úsalo en bots, scripts y dApps que ya gestionan claves y RPC (recomendado para volumen de escrituras en producción). Subscribe y provider-unsubscribe toman un **id** de suscripción — el cliente carga el resto desde la cadena.
</IfFeature>

## Niveles de acceso

| Lane | Superficie | Auth | Límites por defecto (aprox.) |
|------|------------|------|------------------------------|
| **Free** | REST | Ninguno (IP) | 20 rpm; expensive 3 rpm; subgraph 100/día; prepare **2/min · 20/día**; **500 req/día** |
| **Developer** | REST | `Authorization: Bearer ctk_…` | 80 rpm; expensive 40; subgraph 3k/día; prepare **5/min · 100/día**; **5k req/día** |
| **Builder** | REST | SIWE `Bearer cts_…` | Más límites + `:me` cuando hay entitlement configurado (puede estar off) |
| **Agent** | MCP | x402 | 300 rpm; writes 60/min — **no son API keys** |

- **Free** — prueba sin registro; muy medido.
- **Developer** — API key gratuita para integradores; **más límites de lectura**. Prepare sigue estrecho a propósito (la simulación cuesta RPC compartido). Emite keys vía portal / admin.
- **Builder** — entitlement on-chain opcional + SIWE para rutas ligadas a wallet. Ver [auth Builder](/docs/developers/Workflows/builder-auth).
- **MCP** — pago por tool; no envíes keys `ctk_` a MCP.

Consulta `GET /catalog` en `api.clocktower.finance` para el manifiesto en vivo (`writeRpm`, `writeDaily`, `dailyTotalRequests`, `developerKeysEnabled`, `builderAuthEnabled`) y el registro `chains[]`. Selección de cadena REST: [Selección de cadena](/docs/developers/REST%20API/chain-selection).

## Modelo de escritura (solo prepare)

Ni REST ni MCP envían transacciones por ti. Toda escritura sigue:

```
check readiness (opcional) → prepare → firmar en wallet → broadcast → poll status (opcional)
```

Prefiere rutas prepare/readiness **by-id** cuando ya tengas el id de suscripción (`prepare/subscribe_by_id`, etc.).
<IfFeature name="sdk">
Para mucho volumen de escrituras en producción, usa el **SDK con tu propio RPC** en lugar de agotar los cupos REST de prepare.
</IfFeature>
