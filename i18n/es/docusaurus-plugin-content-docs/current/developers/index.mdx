# Visión general para desarrolladores

Clocktower es un protocolo de suscripciones en cadenas EVM.

Si construyes una app, backend o agente de IA que necesita pagos recurrentes, cuentas de suscriptores o datos del protocolo, no tienes que montarlo todo solo con llamadas crudas al contrato.

Ofrecemos dos superficies HTTP<IfFeature name="sdk"> más un SDK TypeScript</IfFeature>:

- **API REST** (`api.clocktower.finance`) — consulta suscripciones, cuentas e historial en una cadena de protocolo seleccionada; prepara transacciones que el usuario firma en su wallet.
- **Servidor MCP** (`mcp.clocktower.finance`) — las mismas capacidades como tools para agentes y clientes MCP, con el mismo acceso free y developer que REST.
<IfFeature name="sdk">
- **SDK TypeScript** — lectura y escritura on-chain directa cuando ya tienes wallet y RPC.
</IfFeature>

Estas superficies responden a las mismas preguntas: *¿Quién está suscrito a qué? ¿Qué vence después? ¿Cómo creo una transacción que suscribe? ¿Qué transacción debe firmar el usuario?*

El uso de REST y MCP alojados se rige por los [Términos de uso](/terms).

## Qué puedes construir

**Con REST**, dashboards, backends y apps de navegador: proveedores y suscriptores, historial de pagos, readiness y calldata preparado para creates, updates, cancels y remits. Tu app prepara; el usuario firma.

**Con MCP**, un agente razona sobre el estado vivo del protocolo: discovery, cuentas y writes preparados con tools MCP estándar. El acceso usa los mismos límites free y API keys de developer opcionales que REST — ideal cuando el llamador es un agente y no tu propio servidor.

<IfFeature name="sdk">
**Con el SDK**, saltas la API para escrituras y hablas con Base o Base Sepolia vía viem. Úsalo en bots, scripts y dApps que ya gestionan claves y RPC (recomendado para volumen de escrituras en producción). Subscribe y provider-unsubscribe toman un **id** de suscripción — el cliente carga el resto desde la cadena.
</IfFeature>

(REST usa Base por defecto (chainId 8453) y acepta `?chainId=` opcional en rutas de protocolo. Las tools MCP aceptan `chainId` opcional y usan Base por defecto<IfFeature name="builder">. SIWE y el entitlement Builder permanecen en Base</IfFeature>.)

- **Free** — prueba sin registro; muy medido.
- **Developer** — API key gratuita para integradores; **más límites de lectura**. Prepare sigue estrecho a propósito (la simulación cuesta RPC compartido). Emite keys en [developers.clocktower.finance](https://developers.clocktower.finance).
<IfFeature name="builder">
- **Builder** — entitlement on-chain opcional + SIWE para rutas ligadas a wallet. Ver [auth Builder](/docs/developers/Workflows/builder-auth).
</IfFeature>
- **MCP** — las mismas credenciales y límites free y developer que REST; envía `ctk_…` como `Authorization` en la conexión MCP.

Consulta `GET /catalog` en `api.clocktower.finance` para el manifiesto en vivo (`writeRpm`, `writeDaily`, `dailyTotalRequests`, `developerKeysEnabled`<IfFeature name="builder">, `builderAuthEnabled`</IfFeature>) y el registro `chains[]`. Selección de cadena REST: [Selección de cadena](/docs/developers/REST%20API/chain-selection).

## Modelo de escritura (solo prepare)

Ni REST ni MCP envían transacciones por ti. Toda escritura sigue:

```
check readiness (opcional) → prepare → firmar en wallet → broadcast → poll status (opcional)
```

Prefiere rutas prepare/readiness **by-id** cuando ya tengas el id de suscripción (`prepare/subscribe_by_id`, etc.).
<IfFeature name="sdk">
Para mucho volumen de escrituras en producción, usa el **SDK con tu propio RPC** en lugar de agotar los cupos REST de prepare.
</IfFeature>
