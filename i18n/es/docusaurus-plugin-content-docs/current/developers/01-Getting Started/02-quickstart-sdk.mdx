# Inicio Rápido SDK

Elige el SDK cuando quieras quedarte on-chain. Si ya ejecutas [viem](https://viem.sh) con tu propio RPC y wallet, puedes leer el estado del protocolo y transmitir escrituras sin pasar por `api.clocktower.finance` ni el servidor MCP.

`@clocktower-protocol/sdk` es una biblioteca TypeScript para esa interacción on-chain. Es una **biblioteca cliente** — no el servidor REST/MCP — pero responde las mismas preguntas sobre suscripciones, cuentas y qué firmar después.

:::warning Pre-lanzamiento
El SDK aún no está publicado en npm. Clona [clocktower-sdk](https://github.com/clocktower-protocol/sdk) y compila desde el código fuente hasta que se anuncie un lanzamiento oficial.
:::

## Instalación

```bash
npm install @clocktower-protocol/sdk viem
```

Dependencias peer para hooks de React: `react`, `wagmi` (^3.0.0), `@tanstack/react-query`.

## Crear una suscripción

Pasa montos en unidades de token legibles para humanos. Requiere un `walletClient` con `account` configurado — consulta [Configuración del cliente](/docs/developers/SDK/client-setup).

```typescript
import { createClocktowerClient, Frequency } from '@clocktower-protocol/sdk'
import { baseSepolia } from 'viem/chains'
import { http } from 'viem'

const client = createClocktowerClient({
  chain: baseSepolia,
  transport: http(process.env.RPC_URL!),
  walletClient, // requerido para escrituras
})

const { hash } = await client.createSubscription({
  amount: '10', // Cargo recurrente en unidades legibles (p. ej. 10 USDC)
  token: '0x036CbD53842c5426634e7929541eC2318f3dCF7e', // Dirección ERC-20; debe estar aprobada por el protocolo
  details: {
    url: 'https://example.com/', // URL del proveedor mostrada a los suscriptores
    description: 'Premium', // Etiqueta breve de la oferta de suscripción
  },
  frequency: Frequency.MONTHLY, // Cadencia de cobro: WEEKLY | MONTHLY | QUARTERLY | YEARLY
  dueDay: 15, // Día dentro del intervalo de frecuencia en que vence el pago (1–28 para MONTHLY)
})
```

## Suscribirse

Pasa un **id** de suscripción. El cliente carga amount, token y provider desde la cadena. Usa `subscribeById` cuando el suscriptor **ya** aprobó al contrato Clocktower para gastar el token de pago.

```typescript
const readiness = await client.checkSubscribeReadiness({
  subscriptionId,
  account: subscriberAddress,
})
if (!readiness.ready) {
  console.log(readiness.errors)
  return
}

const { hash } = await client.subscribeById(subscriptionId, {
  waitForReceipt: true,
})
```

`checkSubscribeReadiness` no lanza. `ready` significa que no hay bloqueos duros; `needsApproval` es true cuando el allowance está por debajo del monto on-chain.

## Suscribirse con aprobación

Usa `subscribeWithApprovalById` para **una sola llamada** que cubre ambos casos: si el allowance ya es suficiente, solo suscribe; si no, envía `approve` primero y luego suscribe. `account` debe coincidir con la wallet conectada.

```typescript
const { approveHash, hash } = await client.subscribeWithApprovalById(
  subscriptionId,
  subscriberAddress, // Wallet que paga; debe tener el token y firmar
  {
    waitForReceipt: true,
    // infiniteApproval: true, // por defecto el approve es acotado al amount
  },
)

// approveHash es undefined cuando el allowance ya estaba configurado; hash es siempre la tx subscribe
```

## Lote approve + subscribe (EIP-5792)

Usa `subscribeWithApprovalAutoById` cuando la wallet pueda soportar `wallet_sendCalls` atómico. Si no, hace fallback a approve + subscribe secuencial.

```typescript
const batchResult = await client.subscribeWithApprovalAutoById(
  subscriptionId,
  subscriberAddress,
)
if (batchResult.mode === 'eip5792') {
  console.log('Batch id:', batchResult.batchId)
} else {
  console.log(batchResult.hash)
}
```

## Darse de baja

Usa `unsubscribe` cuando un suscriptor quiera salir de una suscripción activa. La wallet conectada debe ser la del suscriptor. Las comisiones prepagadas restantes se reembolsan al proveedor.

```typescript
const { hash } = await client.unsubscribe(subscriptionId, {
  waitForReceipt: true,
})
```

## Leer una suscripción

Obtén una suscripción por su id bytes32. Los montos se devuelven en formato legible.

```typescript
const sub = await client.getSubscription('0x...')

console.log(sub.id)             // id bytes32 de la suscripción
console.log(sub.provider)       // wallet que creó la oferta
console.log(sub.amount)         // "10" — cargo recurrente legible
console.log(sub.amountRaw)      // 10000000n — unidades nativas del token
console.log(sub.tokenDecimals)  // 6 — decimales ERC-20 de este token
console.log(sub.chainId)        // 84532 — cadena desde la que se leyó este objeto
console.log(sub.token)          // contrato ERC-20 usado para el pago
console.log(sub.frequencyLabel) // "MONTHLY", "WEEKLY", etc.
console.log(sub.dueDay)         // día de cobro dentro del intervalo de frecuencia
console.log(sub.cancelled)      // true si el proveedor canceló
```

## Leer una cuenta

Lista a qué se suscribe una wallet y qué creó como proveedor. `getEnrichedAccount` agrupa los saldos de comisiones en la vista de suscriptor.

```typescript
const address = '0x...'

// Suscripciones que esta wallet paga
const payingFor = await client.getAccountSubscriptions(true, address)
console.log(payingFor[0]?.subscription.id, payingFor[0]?.statusLabel)

// Suscripciones que esta wallet creó como proveedor
const created = await client.getAccountSubscriptions(false, address)
console.log(created[0]?.subscription.id, created[0]?.totalSubscribers)

// Vista completa de cuenta — subscribedTo incluye saldo de comisiones prepagadas
const account = await client.getEnrichedAccount(address)
console.log(account.subscribedTo[0]?.feeBalance) // comisiones prepagadas restantes
console.log(account.created.length)              // cantidad de ofertas como proveedor
```

## Leer suscriptores

Lista cada suscriptor de una suscripción y su saldo de comisiones prepagadas.

```typescript
const subscribers = await client.getSubscribers('0x...')

console.log(subscribers[0]?.subscriber)    // dirección wallet del suscriptor
console.log(subscribers[0]?.feeBalance)    // comisiones prepagadas restantes (legible)
console.log(subscribers[0]?.feeBalanceRaw) // unidades nativas del token
```

## Leer un token aprobado

Comprueba si un token está habilitado en el protocolo y su monto mínimo de suscripción.

```typescript
const token = await client.getApprovedToken('0x036CbD53842c5426634e7929541eC2318f3dCF7e')

console.log(token.decimals)  // decimales ERC-20
console.log(token.minimum)   // monto mínimo de suscripción permitido (legible)
console.log(token.paused)    // true cuando nuevas suscripciones con este token están bloqueadas
```

## Leer el estado del protocolo

La configuración de comisiones viene de `getProtocolState()`. El calendario de remit y los conteos de vencimientos vienen de `getSubscriptionsDue()`.

```typescript
const state = await client.getProtocolState()

console.log(state.callerFeePercent) // % de cada pago para callers de remit
console.log(state.systemFeePercent) // % de la comisión caller retenido por el protocolo
console.log(state.maxRemits)        // máx. suscripciones procesadas por lote de remit

const due = await client.getSubscriptionsDue()

console.log(due.dueCount)            // suscripciones vencidas en la ventana actual de remit
console.log(due.currentDate)         // día calendario actual del protocolo (UTC)
console.log(due.nextUncheckedDate)   // próximo día que procesará el contrato
console.log(due.isRemitCaughtUp)   // true cuando remit está al día
```
