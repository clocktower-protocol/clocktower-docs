# Inicio rápido de la API REST

Es la forma más rápida de probar Clocktower desde cualquier stack que hable HTTP. Obtienes lecturas y escrituras preparadas sin cliente MCP ni SDK on-chain — solo `curl`, `fetch` o el cliente HTTP que ya uses.

La API REST expone las mismas capacidades que MCP por HTTP estándar. El acceso se controla con límites free y **API keys de developer** opcionales (`ctk_…`)<IfFeature name="builder">, más sesiones Builder SIWE opcionales</IfFeature>. Empieza por el catálogo y una búsqueda de suscripciones; tendrás datos reales del protocolo en menos de un minuto.

## URL base

```
https://api.clocktower.finance
```

En este host, las rutas **omiten** el prefijo `/api` (p. ej. `GET /catalog`). Las URLs legacy `*.workers.dev` mantienen `/api`.

Las rutas de protocolo aceptan `?chainId=` opcional (decimal o CAIP-2, p. ej. `8453` o `eip155:8453`). Si se omite, se usa Base (`8453`). Consulta `GET /catalog` → `chains[]` para ver qué cadenas están activas. Las tools MCP aceptan `chainId` opcional (default Base) — ver [Selección de cadena MCP](/docs/developers/MCP/mcp-chain-selection). Ver [Selección de cadena REST](/docs/developers/REST%20API/chain-selection).

## Leer el estado del protocolo

```bash
curl -s https://api.clocktower.finance/catalog | jq .
curl -s https://api.clocktower.finance/protocol/state | jq .
curl -s "https://api.clocktower.finance/protocol/state?chainId=8453" | jq .
```

Con una key de developer (más límites; comprueba `X-Clocktower-Lane: developer`):

```bash
curl -s https://api.clocktower.finance/catalog \
  -H "Authorization: Bearer <YOUR_API_KEY>" | jq .
```

## Buscar suscripciones

```bash
curl -s "https://api.clocktower.finance/subscriptions?first=10" | jq .
```

Nivel free: `first` máx. 10, sin `includeDetails`. Developer: `first` máx. 25, `includeDetails` permitido.

## Crear una suscripción

`amount` es un string de token legible (p. ej. `"10"`), no wei del protocolo.

`frequency` es `0` semanal, `1` mensual, `2` trimestral, `3` anual.

`details.url` y `details.description` pueden ser strings vacíos.

```bash
curl -s -X POST "https://api.clocktower.finance/prepare/create_subscription?chainId=8453" \
  -H "Content-Type: application/json" \
  -d '{
    "from": "0xProviderAddress",
    "amount": "10",
    "token": "0x...",
    "details": { "url": "https://example.com/", "description": "Premium" },
    "frequency": 1,
    "dueDay": 15
  }' | jq .
```

Ver el [flujo de crear suscripción](/docs/developers/Workflows/create-subscription).

## Suscribirse

Si ya conoces el id de la suscripción, usa endpoints **by-id** (amount, token y provider se cargan on-chain):

```bash
curl -s -X POST "https://api.clocktower.finance/check_subscribe_readiness_by_id?chainId=8453" \
  -H "Content-Type: application/json" \
  -d '{ "from": "0xYourAddress", "id": "0x..." }' | jq .

curl -s -X POST "https://api.clocktower.finance/prepare/subscribe_by_id?chainId=8453" \
  -H "Content-Type: application/json" \
  -d '{ "from": "0xYourAddress", "id": "0x..." }' | jq .
```

Opcional: `"readinessOnly": true` en prepare para preflight sin transacciones sin firmar. La forma por objeto `prepare/subscribe` sigue valiendo cuando ya tienes el objeto completo.

Firma `unsignedTransactions` en tu wallet, haz broadcast a la cadena en `unsignedTransactions[].chainId` y consulta el estado (pasa el mismo `?chainId=`):

```bash
curl -s -X POST "https://api.clocktower.finance/transactions/status?chainId=8453" \
  -H "Content-Type: application/json" \
  -d '{ "txHash": "0x..." }' | jq .
```

Prepare/readiness tiene **límites de tasa** (free: 2/min · 20/día; developer: 5/min · 100/día).

## API key de developer (opcional)

Obtén una key gratuita `ctk_…` en [developers.clocktower.finance](https://developers.clocktower.finance). Envía:

```
Authorization: Bearer <YOUR_API_KEY>
```

Ver [Autenticación](/docs/developers/REST%20API/authentication), [Límites de tasa](/docs/developers/REST%20API/rate-limits) y los [Términos de uso](/terms).

<IfFeature name="builder">
## Sesión Builder (opcional)

Cuando el entitlement Builder está configurado en el servidor, SIWE desbloquea más límites y rutas `:me`:

```bash
# 1. Challenge
curl -s -X POST https://api.clocktower.finance/auth/challenge \
  -H "Content-Type: application/json" \
  -d '{ "address": "0xYourAddress" }'

# 2. Firma el mensaje devuelto con tu wallet (personal_sign)

# 3. Verify
curl -s -X POST https://api.clocktower.finance/auth/verify \
  -H "Content-Type: application/json" \
  -d '{ "message": "...", "signature": "0x..." }'

# 4. Usa el token
curl -s https://api.clocktower.finance/accounts/me/subscriptions \
  -H "Authorization: Bearer cts_..."
```

Ver [Flujo de auth Builder](/docs/developers/Workflows/builder-auth). Builder puede estar **desactivado** si no hay IDs de entitlement (`GET /catalog` → `builderAuthEnabled`).
</IfFeature>

## CLI de ayuda

El repo [clocktower-agent](https://github.com/clocktower-protocol/clocktower-agent) ofrece un CLI en Node:

```bash
npm start rest get /catalog
npm start rest get /protocol/state
npm start rest post /prepare/subscribe_by_id --body '{"from":"0x...","id":"0x..."}'
```
