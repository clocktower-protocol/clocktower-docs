# Endpoints de escritura

Todas las rutas son relativas a `https://api.clocktower.finance`.

Todos los endpoints de escritura usan `POST`. El servidor devuelve transacciones sin firmar — firmas y broadcast desde tu wallet. El servidor **nunca retransmite** transacciones firmadas.

Prepare, readiness y `POST /transactions/status` aceptan `?chainId=` opcional (query string, no cuerpo JSON). La simulación y la estimación de gas corren en la cadena seleccionada. Ver [Selección de cadena](/docs/developers/REST%20API/chain-selection).

## Formato de respuesta prepare

Las respuestas de prepare completo incluyen:

| Campo | Descripción |
|-------|-------------|
| `requestId` | UUID de correlación para soporte (no se almacena en servidor) |
| `instructions` | Pasos ordenados para firmar y hacer broadcast |
| `warnings` | Avisos no fatales (p. ej. remit puede necesitar varias txs) |
| `unsignedTransactions` | Calldata: `to`, `data`, `value`, `chainId`, `from` |
| `signingMode` | `raw` (una tx) o `eip5792` (lote multi-tx) |
| `eip5792` | Descriptor de lote cuando `signingMode` es `eip5792` |
| `simulation` | Simulación on-chain (debe tener éxito antes de liquidar pago MCP) |
| `chainId` | Cadena REST seleccionada (default 8453) |
| `gasEstimates` | Presupuesto de gas por tx en la cadena seleccionada |
| `gasSummary` | Totales agregados; backlogs de remit incluyen `backlogMultiplier` |
| `preflight` | Contexto específico de la operación |

### Campos de request opcionales

En endpoints prepare:

- **`readinessOnly: true`** — solo preflight; sin transacciones sin firmar ni gas estimates
- **`simulateFromAddress`** — dirección para `eth_estimateGas` si el firmante difiere del broadcaster
- **`infiniteApproval: true`** — en subscribe, allowance ERC-20 máxima en lugar de approve acotado al amount

## Rutas by-id preferidas

Si ya tienes el id de suscripción, prefiere endpoints solo por id (la cadena es la fuente de amount/token/provider):

| Endpoint | Descripción |
|----------|-------------|
| `POST /check_subscribe_readiness_by_id` | Readiness con `from` + `id` |
| `POST /prepare/subscribe_by_id` | Prepare subscribe con `from` + `id` |
| `POST /prepare/cancel_subscription_by_id` | Cancel de provider con `from` + `id` |
| `POST /prepare/unsubscribe_by_id` | Unsubscribe de suscriptor con `from` + `id` |
| `POST /prepare/unsubscribe_by_provider_by_id` | Baja por provider con `from` + `id` + `subscriber` |

## Endpoints

Prepare y readiness comparten el bucket **write** (RPM + **write diario**). Por defecto:

| Lane | Write RPM | Write / prepare diario |
|------|-----------|------------------------|
| Free | 2/min | **20/día** |
| Developer | 5/min | **100/día** |

| Endpoint | Descripción |
|----------|-------------|
| `POST /check_subscribe_readiness` | Validar si una cuenta puede suscribirse (forma objeto) |
| `POST /check_subscribe_readiness_by_id` | Igual por id (**preferido** si conoces el id) |
| `POST /prepare/create_subscription` | Prepare nueva suscripción (`amount` = string humano, p. ej. `"10"`) |
| `POST /prepare/subscribe` | Prepare subscribe (forma objeto; incluye approve ERC-20 si hace falta) |
| `POST /prepare/subscribe_by_id` | Prepare subscribe por id (**preferido**) |
| `POST /prepare/cancel_subscription` | Cancel de provider |
| `POST /prepare/cancel_subscription_by_id` | Cancel de provider por id (**preferido**) |
| `POST /prepare/unsubscribe` | Unsubscribe de suscriptor |
| `POST /prepare/unsubscribe_by_id` | Unsubscribe por id (**preferido**) |
| `POST /prepare/unsubscribe_by_provider` | Unsubscribe iniciado por provider |
| `POST /prepare/unsubscribe_by_provider_by_id` | Por id (**preferido**) |
| `POST /prepare/edit_details` | Edición de metadata del provider |
| `POST /check_remit_readiness` | Escaneo multi-día antes de `remit()` |
| `POST /prepare/remit` | Prepare `remit()` permissionless |
| `POST /transactions/status` | Poll de confirmación tras broadcast |

Ver [Límites de tasa](/docs/developers/REST%20API/rate-limits).

## Flujo de remit

```
check_remit_readiness → prepare_remit → firmar → broadcast → repetir hasta ponerse al día
```

Un `remit()` liquida como máximo `maxRemits` pagos por transacción. Usa `get_subscriptions_due` para una lectura ligera de un día; usa `check_remit_readiness` antes de preparar remit.

Ver [Flujo remit caller](/docs/developers/Workflows/remit-caller).
