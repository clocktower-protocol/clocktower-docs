# Autenticación REST

URL base: `https://api.clocktower.finance`. Las rutas siguientes son relativas a ese host (sin prefijo `/api` en el host de producción de la API).

La API REST **no** usa x402. MCP usa x402 únicamente.

La selección de cadena (`?chainId=`) es independiente de la autenticación. SIWE y el entitlement Builder se evalúan siempre en **Base** (8453), aunque una llamada de protocolo apunte a otra cadena. Ver [Selección de cadena](/docs/developers/REST%20API/chain-selection).

| Método | Cuándo |
|--------|--------|
| Ninguno | Nivel **gratis** — llama endpoints con límites por IP |
| `Authorization: Bearer ctk_…` | Nivel **developer** — API key gratuita (más límites de lectura) |
| `Authorization: Bearer cts_…` | Nivel **Builder** — sesión SIWE tras entitlement on-chain (opcional; puede estar desactivado) |
| x402 | **Solo MCP** — no se usa en REST |

Las respuestas REST correctas incluyen `X-Clocktower-Lane: free | developer | builder`.

## Nivel gratis (free)

No se requieren credenciales. Envía las peticiones directamente. Los límites son por **IP**.

- Presupuestos estrictos de prepare/readiness (la simulación es costosa en el RPC compartido).
- Límites de búsqueda: `first` ≤ 10; `includeDetails=true` no permitido.
- Las rutas `:me` devuelven 403 — usa una dirección explícita.

## Nivel developer (API key)

Las API keys de developer gratuitas suben los límites de **lectura** (por **clave**, no por IP). Las keys se emiten desde el portal de developers / mint de admin (hash en reposo; el secreto en claro se muestra **una sola vez** al crearlas).

### Uso de una key

```bash
curl -s https://api.clocktower.finance/catalog \
  -H "Authorization: Bearer <YOUR_API_KEY>"
```

Sustituye `<YOUR_API_KEY>` por el secreto completo (incluido el prefijo `ctk_`).

Keys inválidas o revocadas devuelven **401** (no caen al nivel gratis).

### Guía de producto

- Las keys free y developer son para **exploración y lecturas**.
- Prepare/readiness está limitado a propósito (simulación on-chain y estimación de gas aunque el servidor nunca retransmita txs).
<IfFeature name="sdk">
- Para **volumen de escrituras en producción**, usa el [SDK](/docs/developers/SDK/installation) con **tu propio RPC**.
</IfFeature>

Ver [Límites de tasa](/docs/developers/REST%20API/rate-limits).

## Nivel Builder (sesión SIWE, opcional)

El acceso Builder requiere una suscripción on-chain **ACTIVE** en **Base** a un entitlement de Builder configurado (`BUILDER_SUB_ID` / `BUILDER_SUB_IDS`). El entitlement se comprueba siempre en Base, aunque la llamada REST use otro `?chainId=`. Si no hay IDs configurados, Builder está **desactivado** (`builderAuthEnabled: false` en `GET /catalog`). Challenge/verify SIWE usan chain ID `8453`.

### Flujo

1. `POST /auth/challenge` con `{ "address": "0x…" }` → recibe `message` + `nonce`
2. Wallet `personal_sign` sobre el mensaje
3. `POST /auth/verify` con `{ "message", "signature" }` → recibe `token` (`cts_…`)
4. Envía `Authorization: Bearer cts_…` en las llamadas siguientes

### Alcance Builder

- Cuenta propia (`/accounts/me`, …)
- Suscripciones de contenido a las que te suscribes o creaste
- Discovery y escrituras de suscriptor para tu wallet

Usa free o developer keys para lecturas públicas cross-account cuando Builder esté off o fuera de alcance.

Ver [Flujo de auth Builder](/docs/developers/Workflows/builder-auth).

## Basic Auth opcional

HTTP Basic Auth se controla con `API_REQUIRE_BASIC_AUTH` (por defecto `false`).

## CORS

Las peticiones cross-origin del navegador están desactivadas por defecto. Ops debe permitir orígenes con `API_CORS_ALLOWED_ORIGINS`. CORS no es autenticación y no se concede por una key ni por una suscripción Builder.
