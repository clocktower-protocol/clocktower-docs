# Developer Overview

Clocktower is a subscription protocol on EVM chains. REST defaults to **Base** (chainId 8453) and accepts optional `?chainId=` on protocol routes. **MCP, x402, SIWE, and Builder entitlement stay on Base.**

If you are building an app, backend, or AI agent that needs to work with recurring payments, subscriber accounts, or protocol data, you do not have to stitch everything together from raw contract calls alone.

We provide two HTTP surfaces plus a TypeScript SDK:

- **REST API** (`api.clocktower.finance`) — query subscriptions, accounts, and history on a selected protocol chain; prepare transactions your users sign in their own wallet.
- **MCP server** (`mcp.clocktower.finance`) — the same capabilities exposed as tools for AI agents and MCP clients, with per-call x402 pricing on Base.
- **TypeScript SDK** — read and write on-chain directly when you already have a wallet and RPC.

All three answer the same kinds of questions: *Who is subscribed to what? What is due next? What transaction should the user sign?*

:::warning Pre-release
Production endpoints at `api.clocktower.finance` and `mcp.clocktower.finance` may still be pre-release. Check `GET /catalog` and the quickstarts for current status.
:::

## What you can build

**With REST**, you can power dashboards, backends, and browser apps: look up providers and subscribers, inspect payment history, check whether a subscription is ready to process, and get prepared calldata for creates, updates, cancels, and remits. Your app prepares; the user signs.

**With MCP**, you can let an agent reason over live protocol state: discover subscriptions, inspect accounts, and request prepared writes through standard MCP tools. Each tool call is paid via x402 in USDC on Base — a good fit when the caller is an autonomous agent rather than your own server.

**With the SDK**, you skip the API for writes and talk to Base or Base Sepolia through viem. Use it for bots, scripts, and dApps that already manage their own keys and RPC (recommended for production write volume). Subscribe and provider-unsubscribe take a subscription **id** — the client loads the rest from chain.

## Choose your integration path

| Surface | Best for | Auth | Writes |
|---------|----------|------|--------|
| [REST API](/docs/developers/REST%20API/authentication) | Backends, scripts, browser apps (with CORS) | Free (IP), developer API key (`ctk_…`), or optional Builder SIWE (`cts_…`) | Prepare-only — sign in wallet; tight prepare caps |
| [MCP Server](/docs/developers/MCP/connection) | AI agents and MCP clients | x402 USDC micropayments on Base | Prepare-only — sign in wallet |
| [TypeScript SDK](/docs/developers/SDK/installation) | dApps, Node scripts, bots | Your RPC + wallet (viem) | Direct on-chain via `walletClient` |

For raw on-chain contract structs and function signatures, see the [Contract Technical Reference](/docs/contracts/Subscribe/subscribe_tech_reference).

## Access tiers

| Lane | Surface | Auth | Default limits (approx.) |
|------|---------|------|---------------------------|
| **Free** | REST | None (IP) | 20 rpm; expensive 3 rpm; subgraph 100/day; prepare **2/min · 20/day**; **500 req/day** |
| **Developer** | REST | `Authorization: Bearer ctk_…` | 80 rpm; expensive 40; subgraph 3k/day; prepare **5/min · 100/day**; **5k req/day** |
| **Builder** | REST | SIWE `Bearer cts_…` | Higher limits + `:me` when entitlement IDs are configured (may be off) |
| **Agent** | MCP | x402 | 300 rpm; writes 60/min — **not API keys** |

- **Free** — try without signup; highly metered.
- **Developer** — free API key for integrators; **higher read** limits. Prepare stays intentionally tight (simulation costs shared RPC). Mint keys via the developer portal / admin path.
- **Builder** — optional on-chain entitlement + SIWE for wallet-scoped routes. See [Builder auth](/docs/developers/Workflows/builder-auth).
- **MCP** — pay per tool; do not send `ctk_` keys to MCP.

See `GET /catalog` on `api.clocktower.finance` for the live tier manifest (`writeRpm`, `writeDaily`, `dailyTotalRequests`, `developerKeysEnabled`, `builderAuthEnabled`) and the `chains[]` registry. REST chain selection: [Chain selection](/docs/developers/REST%20API/chain-selection).

## Write model (prepare-only)

Neither REST nor MCP sends transactions for you. Every write follows:

```
check readiness (optional) → prepare → sign in wallet → broadcast → poll status (optional)
```

Prefer **by-id** prepare/readiness routes when you already have a subscription id (`prepare/subscribe_by_id`, etc.). For high-volume production writes, use the **SDK with your own RPC** instead of maxing REST prepare quotas.
