# REST Authentication

Base URL: `https://api.clocktower.finance`. Paths below are relative to that host (no `/api` prefix on the production API host).

The REST API does **not** use x402. MCP uses x402 only.

Use of the hosted API is subject to the [Terms of Use](/terms).

Chain selection (`?chainId=`) is independent of auth.<IfFeature name="builder"> SIWE and Builder entitlement are always evaluated on **Base** (8453), even when a protocol call targets another chain.</IfFeature> See [Chain selection](/docs/developers/REST%20API/chain-selection).

Successful REST responses include an `X-Clocktower-Lane` header of `free` or `developer`<IfFeature name="builder">, or `builder`</IfFeature>.

## Free tier

No credentials required. Send requests directly. Limits are per **IP**.

- Tight prepare/readiness budgets (simulation is expensive on shared RPC).
- Search caps: `first` ≤ 10; `includeDetails=true` not allowed.
<IfFeature name="builder">
- `:me` routes return 403 — use an explicit address.
</IfFeature>

## Developer tier (API key)

Free developer keys raise **read** limits (per **key**, not IP). Keys are issued by the Clocktower developer portal / admin mint path (hashed at rest; plaintext shown **once** on create).

### Using a key

```bash
curl -s https://api.clocktower.finance/catalog \
  -H "Authorization: Bearer <YOUR_API_KEY>"
```

Replace `<YOUR_API_KEY>` with the full secret (including the `ctk_` prefix).

Invalid or revoked keys return **401** (they do **not** fall back to free tier).

### Product guidance

- Free and developer keys are for **exploration and reads**.
- Prepare/readiness is intentionally limited (on-chain simulation/gas estimate even though the server never relays txs).
<IfFeature name="sdk">
- For **production write volume**, use the [SDK](/docs/developers/SDK/installation) with **your own RPC**.
</IfFeature>

See [Rate limits](/docs/developers/REST%20API/rate-limits).

## Builder tier (SIWE session, optional)

Builder access requires an **ACTIVE** on-chain subscription on **Base** to a configured Builder entitlement (`BUILDER_SUB_ID` / `BUILDER_SUB_IDS`). Entitlement is always checked on Base, even if the REST call uses another `?chainId=`. When no entitlement IDs are configured, Builder is **off** (`builderAuthEnabled: false` on `GET /catalog`). SIWE challenge/verify use chain ID `8453`.

### Flow

1. `POST /auth/challenge` with `{ "address": "0x…" }` → receive `message` + `nonce`
2. Wallet `personal_sign` on the message
3. `POST /auth/verify` with `{ "message", "signature" }` → receive `token` (`cts_…`)
4. Send `Authorization: Bearer cts_…` on subsequent calls

### Builder scope

- Own account (`/accounts/me`, …)
- Content subscriptions you subscribe to or created
- Discovery and subscriber writes for your wallet

Use free or developer keys for public cross-account reads when Builder is off or out of scope.

See [Builder auth workflow](/docs/developers/Workflows/builder-auth).
</IfFeature>

## Optional Basic Auth

HTTP Basic Auth is controlled by `API_REQUIRE_BASIC_AUTH` (default `false`).

## CORS

Browser cross-origin requests are disabled by default. Ops must whitelist origins via `API_CORS_ALLOWED_ORIGINS`. CORS is not authentication and is not granted by a key<IfFeature name="builder"> or Builder subscription</IfFeature>.
