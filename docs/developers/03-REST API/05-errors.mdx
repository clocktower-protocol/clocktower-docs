# Error Format

All errors return a consistent JSON shape:

```json
{
  "error": "Human readable message",
  "code": "VALIDATION_ERROR",
  "requestId": "optional-uuid-for-prepare-failures"
}
```

## Error codes

| Code | Description |
|------|-------------|
| `VALIDATION_ERROR` | Invalid request body or parameters, including unknown or malformed `chainId` |
| `NOT_FOUND` | Resource does not exist |
| `UPSTREAM_ERROR` | RPC or subgraph failure |
| `RATE_LIMITED` | Tier rate limit exceeded |
| `PREPARE_FAILURE` | MCP/REST prepare layer failure (may include `requestId`) |

Unsupported REST `?chainId=` (for example `1` or `not-a-chain`) returns **400** with `code: "VALIDATION_ERROR"` and a message such as `Unsupported chainId 1`. See [Chain selection](/docs/developers/REST%20API/chain-selection).

## Validation errors

Write endpoints may include an `issues` array with field-level details:

```json
{
  "error": "Validation failed",
  "code": "VALIDATION_ERROR",
  "issues": [
    { "path": "from", "message": "Invalid address" }
  ]
}
```

## Prepare failures

Include `requestId` when reporting prepare issues. MCP prepare failures return `code: "PREPARE_FAILURE"` when the error originated in the prepare layer.

Simulation failures on MCP throw before x402 payment settles — you are not charged.
