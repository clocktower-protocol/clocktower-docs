# REST API Quickstart

This is the fastest way to poke at Clocktower from any stack that speaks HTTP. You get reads and prepared writes without an MCP client or on-chain SDK — just `curl`, `fetch`, or whatever HTTP client you already use.

The REST API exposes the same capabilities as MCP over standard HTTP. **No x402 payment is required** — access is controlled by free rate limits and optional **developer API keys** (`ctk_…`)<IfFeature name="builder">, plus optional Builder SIWE sessions</IfFeature>. Start with the catalog and a subscription search; you will have real protocol data in under a minute.

## Base URL

```
https://api.clocktower.finance
```

On this host, paths **omit** the `/api` prefix (e.g. `GET /catalog`). Legacy `*.workers.dev` URLs keep `/api`.

Protocol routes accept optional `?chainId=` (decimal or CAIP-2, e.g. `8453` or `eip155:8453`). Omitted uses Base (`8453`). Check `GET /catalog` → `chains[]` for which chains are live. MCP does not take `chainId`. See [Chain selection](/docs/developers/REST%20API/chain-selection).

## Read protocol state

```bash
curl -s https://api.clocktower.finance/catalog | jq .
curl -s https://api.clocktower.finance/protocol/state | jq .
curl -s "https://api.clocktower.finance/protocol/state?chainId=8453" | jq .
```

With a developer key (higher limits; check `X-Clocktower-Lane: developer`):

```bash
curl -s https://api.clocktower.finance/catalog \
  -H "Authorization: Bearer <YOUR_API_KEY>" | jq .
```

## Search subscriptions

```bash
curl -s "https://api.clocktower.finance/subscriptions?first=10" | jq .
```

Free tier: `first` max 10, no `includeDetails`. Developer: `first` max 25, `includeDetails` allowed.

## Preferred: prepare subscribe by id

When you already know the subscription id, use **by-id** endpoints (amount, token, and provider are loaded on-chain):

```bash
curl -s -X POST "https://api.clocktower.finance/check_subscribe_readiness_by_id?chainId=8453" \
  -H "Content-Type: application/json" \
  -d '{ "from": "0xYourAddress", "id": "0x..." }' | jq .

curl -s -X POST "https://api.clocktower.finance/prepare/subscribe_by_id?chainId=8453" \
  -H "Content-Type: application/json" \
  -d '{ "from": "0xYourAddress", "id": "0x..." }' | jq .
```

Optional: `"readinessOnly": true` on prepare for preflight without unsigned transactions.

Object-based `prepare/subscribe` still works when you already hold a full subscription object. Human-readable `subscription.amount` strings (e.g. `"10"`) are required when creating or passing amounts — not protocol wei.

Sign `unsignedTransactions` in your wallet, broadcast to the chain in `unsignedTransactions[].chainId`, then poll status (pass the same `?chainId=`):

```bash
curl -s -X POST "https://api.clocktower.finance/transactions/status?chainId=8453" \
  -H "Content-Type: application/json" \
  -d '{ "txHash": "0x..." }' | jq .
```

Prepare/readiness is **rate-limited** (free: 2/min · 20/day; developer: 5/min · 100/day).

For production write volume, use the [SDK](/docs/developers/SDK/installation) with your own RPC.

## Developer API key (optional)

Obtain a free `ctk_…` key from the developer portal (or admin mint). Send:

```
Authorization: Bearer <YOUR_API_KEY>
```

See [Authentication](/docs/developers/REST%20API/authentication) and [Rate limits](/docs/developers/REST%20API/rate-limits).

<IfFeature name="builder">
## Builder session (optional)

When Builder entitlement is configured on the server, SIWE unlocks higher limits and `:me` routes:

```bash
# 1. Challenge
curl -s -X POST https://api.clocktower.finance/auth/challenge \
  -H "Content-Type: application/json" \
  -d '{ "address": "0xYourAddress" }'

# 2. Sign the returned message with your wallet (personal_sign)

# 3. Verify
curl -s -X POST https://api.clocktower.finance/auth/verify \
  -H "Content-Type: application/json" \
  -d '{ "message": "...", "signature": "0x..." }'

# 4. Use the token
curl -s https://api.clocktower.finance/accounts/me/subscriptions \
  -H "Authorization: Bearer cts_..."
```

See [Builder auth workflow](/docs/developers/Workflows/builder-auth). Builder may be **disabled** when no entitlement IDs are set (`GET /catalog` → `builderAuthEnabled`).
</IfFeature>

## CLI helper

The [clocktower-agent](https://github.com/clocktower-protocol/clocktower-agent) repo provides a Node CLI:

```bash
npm start rest get /catalog
npm start rest get /protocol/state
npm start rest post /prepare/subscribe_by_id --body '{"from":"0x...","id":"0x..."}'
```
