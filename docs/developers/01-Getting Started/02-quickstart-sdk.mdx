# SDK Quickstart

Choose the SDK when you want to stay on-chain. If you already run [viem](https://viem.sh) with your own RPC and wallet, you can read protocol state and broadcast writes without routing through `api.clocktower.finance` or the MCP server.

`@clocktower-protocol/sdk` is a TypeScript library for that on-chain interaction. It is a **client library** — not the REST/MCP server — but it answers the same questions about subscriptions, accounts, and what to sign next.

:::warning Pre-release
The SDK is not published to npm yet. Clone [clocktower-sdk](https://github.com/clocktower-protocol/sdk) and build from source until an official release is announced.
:::

## Installation

```bash
npm install @clocktower-protocol/sdk viem
```

Peer dependencies for React hooks: `react`, `wagmi` (^3.0.0), `@tanstack/react-query`.

## Create a subscription

Pass amounts in human-readable token units. Requires a `walletClient` with `account` configured — see [Client setup](/docs/developers/SDK/client-setup).

```typescript
import { createClocktowerClient, Frequency } from '@clocktower-protocol/sdk'
import { baseSepolia } from 'viem/chains'
import { http } from 'viem'

const client = createClocktowerClient({
  chain: baseSepolia,
  transport: http(process.env.RPC_URL!),
  walletClient, // required for writes
})

const { hash } = await client.createSubscription({
  amount: '10', // Recurring charge in human-readable token units (e.g. 10 USDC)
  token: '0x036CbD53842c5426634e7929541eC2318f3dCF7e', // ERC-20 address; must be approved by the protocol
  details: {
    url: 'https://example.com/', // Provider URL shown to subscribers
    description: 'Premium', // Short label for the subscription offering
  },
  frequency: Frequency.MONTHLY, // Billing cadence: WEEKLY | MONTHLY | QUARTERLY | YEARLY
  dueDay: 15, // Day within the frequency window when payment is due (1–28 for MONTHLY)
})
```

## Subscribe

Use `subscribe` when the subscriber has **already** approved the Clocktower contract to spend the payment token. The SDK checks allowance in preflight and throws if it is still too low.

```typescript
const subscription = await client.getSubscription(subscriptionId)

const { hash } = await client.subscribe(subscription, {
  waitForReceipt: true,
})
```

## Subscribe with approval

Use `subscribeWithApproval` when you want **one call** that handles both cases: if allowance is already sufficient, it subscribes only; if not, it sends `approve` first, then subscribes.

```typescript
const subscription = await client.getSubscription(subscriptionId)

const { approveHash, hash } = await client.subscribeWithApproval(
  subscription, // Subscription to join — from getSubscription
  subscriberAddress, // Paying wallet; must hold the token and sign the transactions
  { waitForReceipt: true }, // Wait for each tx receipt before returning
)

// approveHash is undefined when allowance was already set; hash is always the subscribe tx
```

## Approve, then subscribe

Use two explicit steps when you want the subscriber to confirm the ERC-20 `approve` before you call `subscribe` yourself.

```typescript
import { maxUint256 } from 'viem'

const usdcAbi = [
  {
    type: 'function',
    name: 'approve',
    stateMutability: 'nonpayable',
    inputs: [
      { name: 'spender', type: 'address' },
      { name: 'amount', type: 'uint256' },
    ],
    outputs: [{ name: '', type: 'bool' }],
  },
] as const

const subscription = await client.getSubscription(subscriptionId)

// Standard ERC-20 approve — USDC uses the same interface as any ERC-20 token
await walletClient.writeContract({
  address: subscription.token,
  abi: usdcAbi,
  functionName: 'approve',
  args: [client.contractAddress, maxUint256],
})

// Clocktower subscribe — enrolls the wallet and charges the prorated first payment
const { hash } = await client.subscribe(subscription, {
  waitForReceipt: true,
})
```

## Unsubscribe

Use `unsubscribe` when a subscriber wants to leave an active subscription. The connected wallet must be the subscriber. Remaining prepaid fees are refunded to the provider.

```typescript
const { hash } = await client.unsubscribe(subscriptionId, {
  waitForReceipt: true,
})
```

## Read a subscription

Fetch one subscription by its bytes32 id. Amounts are returned in human-readable form.

```typescript
const sub = await client.getSubscription('0x...')

console.log(sub.id)             // bytes32 subscription id
console.log(sub.provider)       // wallet that created the offering
console.log(sub.amount)         // "10" — human-readable recurring charge
console.log(sub.amountRaw)      // 10000000n — token-native units
console.log(sub.tokenDecimals)  // 6 — ERC-20 decimals for this token
console.log(sub.token)          // ERC-20 contract used for payment
console.log(sub.frequencyLabel) // "MONTHLY", "WEEKLY", etc.
console.log(sub.dueDay)         // billing day within the frequency window
console.log(sub.cancelled)      // true if the provider cancelled
```

## Read an account

List what a wallet subscribes to and what it created as a provider. `getEnrichedAccount` batches fee balances into the subscriber view.

```typescript
const address = '0x...'

// Subscriptions this wallet pays into
const payingFor = await client.getAccountSubscriptions(true, address)
console.log(payingFor[0]?.subscription.id, payingFor[0]?.statusLabel)

// Subscriptions this wallet created as provider
const created = await client.getAccountSubscriptions(false, address)
console.log(created[0]?.subscription.id, created[0]?.totalSubscribers)

// Full account view — subscribedTo includes prepaid fee balance per subscription
const account = await client.getEnrichedAccount(address)
console.log(account.subscribedTo[0]?.feeBalance) // prepaid fees remaining
console.log(account.created.length)              // count of provider offerings
```

## Read subscribers

List every subscriber on a subscription and their prepaid fee balance.

```typescript
const subscribers = await client.getSubscribers('0x...')

console.log(subscribers[0]?.subscriber)   // subscriber wallet address
console.log(subscribers[0]?.feeBalance)   // prepaid fees remaining (human-readable)
console.log(subscribers[0]?.feeBalanceRaw) // token-native units
```

## Read an approved token

Check whether a token is enabled on the protocol and its minimum subscription amount.

```typescript
const token = await client.getApprovedToken('0x036CbD53842c5426634e7929541eC2318f3dCF7e')

console.log(token.decimals)  // ERC-20 decimals
console.log(token.minimum)   // smallest allowed subscription amount (human-readable)
console.log(token.paused)    // true when new subscriptions using this token are blocked
```

## Read protocol state

Fee configuration comes from `getProtocolState()`. Remit schedule and due counts come from `getSubscriptionsDue()`.

```typescript
const state = await client.getProtocolState()

console.log(state.callerFeePercent) // % of each payment paid to remit callers
console.log(state.systemFeePercent) // % of caller fee retained by the protocol
console.log(state.maxRemits)        // max subscriptions processed per remit batch

const due = await client.getSubscriptionsDue()

console.log(due.dueCount)           // subscriptions due in the current remit window
console.log(due.currentDate)      // today's protocol calendar day (UTC)
console.log(due.nextUncheckedDate) // next day the contract will process
console.log(due.isRemitCaughtUp)  // true when remit is up to date
```
